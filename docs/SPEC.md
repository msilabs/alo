# Alo — ইমপ্লিমেন্টেশন প্ল্যান (v1)

> **Alo (আলো) — lightweight static web framework**
> HTML, CSS আর JS লিখুন, সাথে পান কম্পোনেন্ট, লেআউট আর সহজ লুপ ও শর্ত। বিল্ড করলে পাবেন পুরোপুরি স্ট্যাটিক সাইট। Node.js ছাড়া আর কিছু লাগে না।
>
> প্যাকেজ: `@msilabs/alo` · ফাইল এক্সটেনশন: `.alo` · CLI: `alo`

> **Claude-এর জন্য নির্দেশনা:** এই ডকুমেন্টে পুরো ফ্রেমওয়ার্কের স্পেসিফিকেশন আছে। কোড লেখার আগে সম্পূর্ণ ডকুমেন্টটি পড়ুন। অংশ ২৩-এর মাইলস্টোনগুলো একটি একটি করে শেষ করুন, আর প্রতিটির শেষে টেস্ট চালান। স্পেকে কিছু অস্পষ্ট বা পরস্পরবিরোধী মনে হলে নিজে অনুমান করে বড় সিদ্ধান্ত নেবেন না, আগে জিজ্ঞাসা করুন। ছোট সিদ্ধান্ত নিলে `DECISIONS.md` ফাইলে লিখে রাখুন; শুরু করুন অংশ ২৫-এর তালিকা দিয়ে। অংশ ২-এর "কখনো না" আর "বাতিল" তালিকায় কিছু যোগ করবেন না, এমনকি সুবিধাজনক মনে হলেও। নতুন কোনো ফিচার বা নিয়ম যোগ করার আগে অংশ ০-এর তিন প্রশ্নের পরীক্ষা করুন।

## ০. এক পাতায় Alo

এই অংশটিই ফ্রেমওয়ার্কের পরিচয়। এখানে যা নেই, ব্যবহারকারীকে তা শিখতে হবে না।

1. **পেইজ:** `pages/about/page.alo` মানে `/about/`।
2. **লেআউট:** `layout.alo` তার ফোল্ডারের সব পেইজকে মোড়ায়। পেইজ বসে `<slot />`-এর জায়গায়।
3. **কম্পোনেন্ট:** `components/Card.alo` থাকলে লেখা যায় `<Card title="হ্যালো" />`। অ্যাট্রিবিউটই প্রপস; কম্পোনেন্টের ভেতরে পড়ুন `{{ props.title }}`।
4. **ডেটা:** `data/team.json` হয় `data.team`। `data/blog/` ফোল্ডারের JSON বা Markdown ফাইলগুলো হয় `data.blog` অ্যারে।
5. **টেমপ্লেট:** `{{ }}` দিয়ে মান বসানো। লুপ আর শর্ত লেখা হয় শুধু `<template>` ট্যাগে: `for`, `if`, `else-if`, `else`।
6. **CSS:** `<style>`-এর CSS শুধু সেই ফাইলে প্রযোজ্য হয়। `global/` ফোল্ডারের CSS প্রযোজ্য হয় সব পেইজে।
7. **JS:** `<script>`-এ সাধারণ JS। কম্পোনেন্টের নিজের এলিমেন্ট পাওয়া যায় `$el` দিয়ে।
8. **ডায়নামিক পেইজ:** `pages/blog/[slug]/page.alo` প্রতিটি পোস্টের জন্য একটি পেইজ বানায়; পোস্টের ডেটা থাকে `item`-এ।

### পুরো টেমপ্লেট সিনট্যাক্স

| লিখবেন                                                     | কাজ                                      |
| ---------------------------------------------------------- | ---------------------------------------- |
| `{{ x }}`                                                  | মান বসানো                                |
| `{{{ html }}}`                                             | এস্কেপ ছাড়া HTML (যেমন Markdown-এর বডি) |
| `<template for="x in list">`                               | লুপ                                      |
| `<template if>` / `<template else-if>` / `<template else>` | শর্ত                                     |
| `<Card title="…" post="{{ post }}" />`                     | কম্পোনেন্ট আর প্রপস                      |
| `<slot />`                                                 | লেআউট বা কম্পোনেন্টে কনটেন্টের জায়গা    |

### নতুন ফিচারের পরীক্ষা (তিন প্রশ্ন)

কোনো ফিচার বা নিয়ম যোগ করার আগে:

1. **HTML জানা কেউ ফাইলটি দেখে কি অনুমান করতে পারবে কী হচ্ছে?**
2. **ব্যবহারকারীকে কি এটি শিখতে হয়, নাকি নিজে থেকেই ঘটে?** নিজে থেকে ঘটলে শেখার খরচ শূন্য।
3. **ছোট সাইটের (ব্লগ, পোর্টফোলিও, কোম্পানির সাইট) কি সত্যিই এটি লাগে?**

প্রথম প্রশ্নে "না" হলে ফিচারটি যোগ হবে না। দ্বিতীয় প্রশ্নে "শিখতে হয়" আর তৃতীয়তে "না" হলে সেটি পরে ভাবা হবে।

## ১. লক্ষ্য ও মূলনীতি

Alo একটি বিল্ড-টাইম টুল। ডেভেলপার `.alo` ফাইলে সাধারণ HTML, CSS আর JS লেখে; কনটেন্ট থাকে JSON বা Markdown-এ। বিল্ড করলে পুরোপুরি স্ট্যাটিক HTML, CSS আর JS তৈরি হয়, যা যেকোনো স্ট্যাটিক হোস্টিংয়ে চলে।

এই নীতিগুলো কোনো অবস্থাতেই ভাঙা যাবে না:

1. **খাঁটি HTML, CSS, JS।** কোনো নতুন ভাষা নেই। বাড়তি উপাদান শুধু অংশ ০-এর টেবিলে যা আছে, আর সব বিল্ডের সময়েই শেষ হয়ে যায়। লজিক থাকে শুধু `<template>` ট্যাগে, তাই বাকি সব এলিমেন্ট সবসময় খাঁটি HTML থাকে।
2. **কোনো ইমপোর্ট নয়।** কম্পোনেন্ট, ডেটা, CSS আর JS সব আসে ফাইলের অবস্থান দেখে। ব্যবহারকারীকে কোথাও `import`, `require`, `<link>` বা `<script src>` লিখতে হয় না।
3. **রিঅ্যাক্টিভিটি নয়, স্টেট নয়।** ব্রাউজারে কোনো রিঅ্যাক্টিভ সিস্টেম, স্টেট, বাইন্ডিং বা ভার্চুয়াল DOM নেই। ব্রাউজারে চলে শুধু ব্যবহারকারীর লেখা সাধারণ JS, সাথে কম্পোনেন্ট স্ক্রিপ্ট চালানোর একটি ছোট ইনিশিয়ালাইজার, তাও শুধু যে পেইজে দরকার।
4. **জিরো ডিপেন্ডেন্সি।** শুধু Node.js-এর বিল্ট-ইন মডিউল (`fs`, `path`, `http`, `crypto`, `url`, `node:test` ইত্যাদি)। কোনো npm প্যাকেজ নয়, dev-ডিপেন্ডেন্সি হিসেবেও নয়। কোনো বান্ডলার নয়। Markdown, YAML ফ্রন্ট ম্যাটার আর CSS মিনিফায়ার আমরা নিজেরা লিখব।
5. **জিরো কনফিগারেশন।** কোনো কনফিগারেশন ফাইল নেই। সব আচরণ ঠিক হয় ফোল্ডার আর ফাইলের নাম থেকে। CLI ফ্ল্যাগ মোট দুটি: `--port` (dev) আর `--base` (dev, build)।
6. **Node.js ≥ 22।** Node 20-এর সহায়তার মেয়াদ (end of life) শেষ হয়েছে ৩০ এপ্রিল ২০২৬-এ। নীতি হলো: Node নিজে যে লাইনগুলো সমর্থন করে, Alo-ও শুধু সেগুলো করে। CI-তে 22, 24 আর 26-এ টেস্ট চলবে। Node 22-এর EOL ৩০ এপ্রিল ২০২৭; তখন ন্যূনতম ভার্সন `>=24` হবে। `package.json`-এ লেখা থাকবে `"engines": { "node": ">=22" }`। CLI শুরুতেই ভার্সন যাচাই করে পরিষ্কার এরর দেবে।
7. **ফোল্ডার মানে সাজানোর উপায়, সীমানা নয়।** কম্পোনেন্ট আর ডেটা সব জায়গায় ব্যবহার করা যায়।
8. **পাঁচ মিনিটে শেখা যায়।** অংশ ০ পড়লেই কাজ শুরু করা যায়। এর বাইরের সবকিছু হয় নিজে থেকে ঘটে, নয়তো README-র "পরে দেখুন" অংশে থাকে।
9. **যা স্বাভাবিক, তা-ই ঘটে।** ব্যবহারকারীকে বিশেষ ক্ষেত্র মনে রাখতে হবে না। যেমন `disabled="{{ x }}"` লিখলে x মিথ্যা হলে `disabled` নিজে থেকেই বাদ যায়।
10. **ভালো এরর মেসেজ।** প্রতিটি এররে ফাইলের পাথ, লাইন নম্বর আর সম্ভব হলে সমাধানের ইঙ্গিত থাকবে। টার্মিনালের সব লেখা ইংরেজিতে, কারণ অনেক টার্মিনালে বাংলা যুক্তাক্ষর ভেঙে যায় (`DECISIONS.md` #৮৪)। এই স্পেকে উদ্ধৃত মেসেজগুলো অর্থ বোঝাতে বাংলায় লেখা; আসল লেখা ইংরেজি।
11. **core আর cli আলাদা।** কম্পাইলার (core) ডিস্কে লেখে না; ইনপুট নিয়ে আউটপুট ফাইলের তালিকা দেয়।

## ২. স্কোপ

### v1

- পেইজ রাউটিং, নেস্টেড লেআউট, রাউট গ্রুপ `(name)`, `not-found`
- এক লেভেলের ডায়নামিক রাউট `[slug]`
- কম্পোনেন্ট (ডট-যুক্ত নাম), প্রপস, `<slot />`
- `data/`: JSON আর Markdown (YAML ফ্রন্ট ম্যাটারসহ), খসড়া, ফাইলনেম থেকে তারিখ
- `<template>`-এ `for`, `if`, `else-if`, `else`
- স্কোপড CSS, `<style global>`, `global/` CSS ও JS, `$el`
- প্রোডাকশন আউটপুট (নিজে থেকে হয়): ফাইলনেমে হ্যাশ, CSS মিনিফাই, `sitemap.xml`, `robots.txt`
- base path (`--base`)
- লাইভ রিলোডসহ dev সার্ভার
- CLI কমান্ড `init`, `dev`, `build`, `new`; প্রজেক্টের রুটে `alo` ফাইল
- পরিষ্কার এরর মেসেজ (ইংরেজিতে), বাংলা README, উদাহরণ সাইট

### পরে ভাবা হবে (আসল ব্যবহারকারীরা চাইলে, আর অংশ ০-এর পরীক্ষা পাস করলে)

পেজিনেশন, নামযুক্ত স্লট, একাধিক লেভেলের ডায়নামিক রাউট, JS মিনিফাই, VS Code এক্সটেনশন, প্রাইভেট কম্পোনেন্ট, প্রপস ঘোষণা।

### কখনো না

reactivity, state, store, `bind:`/`on:` ধাঁচের বাইন্ডিং, ভার্চুয়াল DOM, SPA বা ক্লায়েন্ট-সাইড রাউটিং, ইমপোর্ট সিস্টেম, কনফিগারেশন ফাইল, প্লাগইন সিস্টেম, TypeScript, সার্ভার-সাইড রেন্ডারিং।

বেশি ইন্টারঅ্যাকটিভিটি দরকার হলে ব্যবহারকারী নিজে Alpine.js বা MiniJS যোগ করবে। Alo শুধু নিশ্চিত করবে যে তাদের অ্যাট্রিবিউট আউটপুটে অপরিবর্তিত থাকে।

### বাতিল করা বিকল্প (আবার আনবে না)

| বাতিল                                            | বদলে যা আছে                                 | কারণ                                                                   |
| ------------------------------------------------ | ------------------------------------------- | ---------------------------------------------------------------------- |
| `<@Folder@Component />`                          | `<Folder.Component />`                      | `<@` HTML ট্যাগ হিসেবে বৈধ নয়; এডিটর আর হাইলাইটিং ভেঙে যায়           |
| `{ expr }`                                       | `{{ expr }}`                                | Alpine.js-এর `x-data="{ ... }"`, ইনলাইন JS আর কোড উদাহরণের সাথে সংঘর্ষ |
| `a:text="expr"`                                  | `{{ expr }}`                                | প্রতিটি মানে আলাদা এলিমেন্ট লাগে; দেখে রানটাইম বাইন্ডিং মনে হয়        |
| `<Data.item />`                                  | `{{ data.item }}`                           | অ্যাট্রিবিউটে বসানো যায় না; কম্পোনেন্টের ডট-যুক্ত নামের সাথে সংঘর্ষ        |
| `@if ... @endif`, `@foreach`                     | `<template if>`, `<template for>`           | HTML কাঠামো মানে না; এডিটর বোঝে না; `@click` আর `@media`-র সাথে সংঘর্ষ |
| `a-if`, `a-for`, `a-else`                        | `if`, `for`, `else-if`, `else`              | লজিক শুধু `<template>`-এ থাকে বলে উপসর্গ লাগে না; পড়তে সহজ            |
| সাধারণ এলিমেন্টে লজিক (`<li for>`)               | `<template for><li>…</li></template>`       | সাধারণ HTML খাঁটি রাখা                                                 |
| কম্পোনেন্ট ট্যাগে লজিক (`<Card for>`)            | `<template for><Card /></template>`         | এক নিয়ম, কোনো ব্যতিক্রম নেই; `for`-এর মতো নাম প্রপের সাথে মেশে না     |
| `else-if` ছাড়া শুধু নেস্টিং                     | `<template else-if>`                        | সবাই if / else if / else চেনে; নেস্টিং পড়তে খারাপ                     |
| `:prop="expr"`                                   | `prop="{{ expr }}"`                         | একটিই সিনট্যাক্স (`{{ }}`) সব জায়গায়; নতুন চিহ্ন শিখতে হয় না        |
| নাম ধরে প্রপ পড়া (`{{ title }}`)               | `{{ props.title }}`                         | এক নিয়ম; `class`-এর ব্যতিক্রম নেই; লুপ ভেরিয়েবল বা গ্লোবালের সাথে মেশে না |
| `$props` আর পেইজে JSON                           | `data-*` অ্যাট্রিবিউট + `$el.dataset`       | খাঁটি HTML; কোনো লুকানো রানটাইম ডেটা নেই                               |
| `:global(.x)`                                    | `<style global>` বা `class` প্রপ            | CSS-এ নতুন সিনট্যাক্স নেই                                              |
| `_` দিয়ে প্রাইভেট কম্পোনেন্ট                    | সব কম্পোনেন্ট সব জায়গায়                   | ছোট সাইটে লাগে না, অথচ নিয়মটি জটিল                                    |
| `params` ভেরিয়েবল                               | শুধু `item` (`item.slug` সহ)                | একই তথ্য দুই জায়গায় রাখার দরকার নেই                                  |
| `[id]`, `[name]` ইত্যাদি যেকোনো নাম              | শুধু `[slug]`                               | মনে রাখার কিছু নেই                                                     |
| ইমপোর্ট (`import`, `<data from>`)                | ফোল্ডার = ডট-যুক্ত নাম                           | "কোনো ইমপোর্ট নয়" নীতি                                                |
| HTML ট্যাগের নামে কম্পোনেন্ট নিষেধ               | বড় হাতের অক্ষর দিয়ে শুরু = সবসময় কম্পোনেন্ট           | `Header`, `Button`-এর মতো সাধারণ নাম আটকে যেত                          |
| reactivity, state, store                         | সাধারণ JS + `$el`                           | খাঁটি HTML, CSS, JS নীতি                                                |
| base path-এর জন্য কনফিগারেশন ফাইল বা `site.json`      | `--base` ফ্ল্যাগ                            | জিরো কনফিগারেশন                                                             |
| JSON ফ্রন্ট ম্যাটার                              | YAML-এর ছোট সাবসেট                          | লিখতে স্বাভাবিক, পরিচিত                                                |
| প্রপস ঘোষণা (`a-props`), `_meta.json`, `parents` | প্রপের টাইপোতে সতর্কবার্তা, এক লেভেলের রাউট | নতুন কিছু শেখা ছাড়াই সমাধান                                         |

## ৩. ইনস্টল আর প্রজেক্ট শুরু

Alo সিস্টেমজুড়ে (global) ইনস্টল হয় না; প্রতিটি প্রজেক্টে আলাদা থাকে:

```bash
npx @msilabs/alo init my-site
cd my-site
npm install
node alo dev
```

### রুটের `alo` ফাইল

`init` প্রজেক্টের রুটে এক্সটেনশন ছাড়া `alo` নামে একটি ফাইল বানাবে:

```js
#!/usr/bin/env node
try {
    require('@msilabs/alo/cli');
} catch (e) {
    if (
        e.code === 'MODULE_NOT_FOUND' &&
        String(e.message).includes('@msilabs/alo')
    ) {
        console.error('Alo is not installed. Run `npm install` first.');
        process.exit(1);
    }
    throw e;
}
```

একই কাজ তিনভাবে চালানো যায়, আর তিনটিই প্রজেক্টের নিজের ভার্সন চালায়:

| কমান্ড         | কাদের জন্য স্বাভাবিক                                  |
| -------------- | ----------------------------------------------------- |
| `node alo dev` | সবার জন্য, কিছু জানা লাগে না (README-তে এটিই ডিফল্ট) |
| `npm run dev`  | JS ডেভেলপার                                           |
| `npx alo dev`  | যারা npm-এর লোকাল কমান্ডে অভ্যস্ত                     |

`init` যে `package.json` বানাবে:

```json
{
    "name": "my-site",
    "private": true,
    "engines": { "node": ">=22" },
    "scripts": {
        "dev": "alo dev",
        "build": "alo build"
    },
    "devDependencies": {
        "@msilabs/alo": "^<বর্তমান ভার্সন>"
    }
}
```

`init` আরও বানাবে: উদাহরণ পেইজ, কম্পোনেন্ট, ডেটা আর Markdown পোস্ট; `.gitignore` (`node_modules/`, `dist/`, `.alo/`); `.gitattributes`; `.vscode/settings.json` (অংশ ২১)।

## ৫. `.alo` ফাইল ফরম্যাট

একটি ফাইলে নিচের টপ-লেভেল ব্লকগুলো থাকতে পারে, প্রতিটি সর্বোচ্চ একবার। সব ঐচ্ছিক, ক্রম যেকোনো।

| ব্লক                         | কোথায় চলে   | কাজ                     |
| ---------------------------- | ------------ | ----------------------- |
| `<head>`                     | page, layout | টাইটেল, মেটা, লিংক      |
| `<template>`                 | সব           | HTML মার্কআপ            |
| `<style>` / `<style global>` | সব           | স্কোপড বা গ্লোবাল CSS   |
| `<script>`                   | সব           | ব্রাউজারে চলা সাধারণ JS |

নিয়ম:

- কম্পোনেন্টে `<head>` থাকলে এরর।
- টপ-লেভেলে অজানা ব্লক থাকলে বা ব্লকের বাইরে কিছু লেখা থাকলে এরর। শুধু হোয়াইটস্পেস আর HTML কমেন্ট চলবে।
- একই ব্লক দুবার থাকলে এরর।
- টপ-লেভেল ব্লকে কোনো অ্যাট্রিবিউট থাকলে এরর। একমাত্র ব্যতিক্রম `<style global>`।
- লেআউটের `<template>`-এ ঠিক একটি `<slot />` থাকতে হবে।
- টপ-লেভেলের `<template>` ব্লক আর তার ভেতরের `<template>` ট্যাগ আলাদা বিষয়। প্রথমটি ফাইলের ব্লক; দ্বিতীয়টি হয় লজিক, নয়তো সাধারণ HTML `<template>` (অংশ ৭)।
- কোনো `<template>`-এ `<html>`, `<head>` বা `<body>` ট্যাগ থাকলে এরর। এগুলো Alo নিজে বানায়।

উদাহরণ কম্পোনেন্ট (`components/Faq.alo`):

```html
<template>
    <div class="faq">
        <button>{{ props.question }}</button>
        <p>{{ props.answer }}</p>
    </div>
</template>

<style>
    p {
        display: none;
    }
    .open p {
        display: block;
    }
</style>

<script>
    $el.querySelector('button').addEventListener('click', () => {
        $el.classList.toggle('open');
    });
</script>
```

## ৬. HTML পার্সার

একটি নিজস্ব সহনশীল (tolerant) HTML টোকেনাইজার আর পার্সার লাগবে। প্রয়োজনীয়তা:

- **ট্যাগের নামের কেস হুবহু রাখবে।** `<Card>` আর `<card>` আলাদা। SVG-র `<linearGradient>`, `<clipPath>` কেসসহ আউটপুটে যাবে।
- ট্যাগের নামে `.` থাকতে পারবে (`<Blog.PostCard />`)।
- void এলিমেন্ট (`br`, `img`, `input`, `meta`, `link`, `hr` ইত্যাদি) আর self-closing ট্যাগ (`<Card />`, `<slot />`) সমর্থন করবে।
- `<script>` আর `<style>`-এর ভেতরের লেখা raw text; এদের ভেতরে `{{ }}` প্রসেস হবে না। `<pre>` আর `<textarea>` সাধারণ এলিমেন্ট: ভেতরে `{{ }}` চলে, আর হোয়াইটস্পেস হুবহু থাকে (`DECISIONS.md` #১৯)।
- `<template>` ব্লকের ভেতরের `<template>` ট্যাগকে সাধারণ এলিমেন্ট হিসেবে পার্স করবে, raw text হিসেবে নয়।
- **`{{ … }}` আর `{{{ … }}}` একটি অবিভাজ্য টোকেন।** লেখায় বা অ্যাট্রিবিউটের মানে `{{` পেলে মিলিয়ে বন্ধ হওয়া `}}` পর্যন্ত পুরো অংশ একটি টুকরো হিসেবে পড়বে। ভেতরের `<`, `>` বা কোট দিয়ে ট্যাগ বা অ্যাট্রিবিউট ভাঙবে না। তাই `{{ a > b }}` আর `title="{{ x === "a" ? 'হ্যাঁ' : 'না' }}"` দুটিই ঠিকমতো পার্স হবে। এক্সপ্রেশনের ভেতরের JS স্ট্রিং আর টেমপ্লেট লিটারালে `}}` থাকতে পারে, তাই টোকেনাইজারকে সেগুলো চিনতে হবে। বন্ধ না হওয়া `{{`-এ লাইন নম্বরসহ এরর।
- অ্যাট্রিবিউটের চার ধরন সমর্থন করবে: ডাবল কোট, সিঙ্গেল কোট, কোট ছাড়া, আর মান ছাড়া (বুলিয়ান)। নামে `:`, `@`, `.`, `-` থাকলেও ঠিকমতো পার্স হবে।
- **অচেনা অ্যাট্রিবিউট হুবহু রাখবে।** `:click`, `@click`, `x-data` ইত্যাদি (Alpine.js, MiniJS) অপরিবর্তিত আউটপুটে যাবে।
- HTML কমেন্ট আর হোয়াইটস্পেস যেমন আছে তেমন রাখবে।
- প্রতিটি নোডে সোর্সের লাইন আর কলাম নম্বর থাকবে।
- বন্ধ না করা বা ভুল ক্রমে বন্ধ করা ট্যাগে লাইন নম্বরসহ এরর।

## ৭. টেমপ্লেট সিনট্যাক্স

### ইন্টারপোলেশন `{{ }}`

- `{{ expr }}`: বিল্ডের সময় এক্সপ্রেশন চালিয়ে ফলাফল HTML-এস্কেপ করে বসায় (`&` `<` `>` `"` `'`)। লেখার জায়গায় আর অ্যাট্রিবিউটের মানে (পুরো মান বা তার অংশ) দুই জায়গাতেই চলে: `<a href="/blog/{{ post.slug }}/">{{ post.title }}</a>`।
- `{{{ expr }}}`: এস্কেপ ছাড়া raw HTML। শুধু লেখার জায়গায় চলে; অ্যাট্রিবিউটে থাকলে এরর।
- লেখায় `undefined` আর `null` খালি স্ট্রিং হয়ে যায়। সংখ্যা আর বুলিয়ান লেখায় রূপান্তরিত হয়। অবজেক্ট বা অ্যারে হলে সতর্কবার্তা।
- ট্যাগের নামে বা অ্যাট্রিবিউটের নামে `{{ }}` থাকলে এরর। `<script>` আর `<style>`-এর ভেতরে প্রসেস হয় না।
- আক্ষরিক `{{` লিখতে হলে `\{{`।

### HTML অ্যাট্রিবিউটে `{{ }}` — যা স্বাভাবিক, তা-ই ঘটে

এই নিয়মগুলো প্রযোজ্য হয় শুধু তখন, যখন অ্যাট্রিবিউটের **পুরো মান** একটি `{{ expr }}`:

- মান `null` বা `undefined` হলে **অ্যাট্রিবিউটটিই বাদ যায়**: `<img alt="{{ item.alt }}">`-এ alt না থাকলে আউটপুটে `alt` থাকে না।
- HTML-এর বুলিয়ান অ্যাট্রিবিউটে (`disabled`, `checked`, `selected`, `hidden`, `required`, `readonly`, `open`, `multiple`, `autofocus`, `inert`, `novalidate`, `defer`, `async`, `controls`, `loop`, `muted`, `playsinline`, `default`, `reversed`, `formnovalidate`, `itemscope`, `allowfullscreen`): মিথ্যা মান হলে অ্যাট্রিবিউট বাদ যায়, সত্য মান হলে মান ছাড়া বসে। তাই `<button disabled="{{ !item.ready }}">` যা বোঝায় ঠিক তা-ই করে।
- অন্য অ্যাট্রিবিউটে `false` লেখা হয় `"false"` (যেমন `aria-expanded="false"`)।

মানের অংশে `{{ }}` থাকলে (`class="card {{ x }}"`) সবসময় স্ট্রিং হয়। এই নিয়মগুলো সেখানে প্রযোজ্য হয় না।

### এক্সপ্রেশন

- এক্সপ্রেশন হলো সাধারণ JavaScript, যা **বিল্ডের সময়** Node-এ চলে। চালানো হয় `new Function` দিয়ে, স্কোপের ভেরিয়েবল যায় প্যারামিটার হিসেবে। কম্পাইল করা ফাংশন ক্যাশ হয়।
- **ফাংশনের বডি সবসময় `"use strict"` দিয়ে শুরু হবে।** না হলে frozen অবজেক্টে মান বসানোর চেষ্টা নীরবে ব্যর্থ হয়।
- অজানা ভেরিয়েবলে এরর, সাথে ফাইল, লাইন আর ওই স্কোপে কোন কোন ভেরিয়েবল আছে তার তালিকা।
- ডেটা পরিবর্তন করা যাবে না (অংশ ১০)। `.reverse()`, `.sort()`, `.push()` বা মান বসানোর চেষ্টায় এরর, সাথে ইঙ্গিত: "Make a new value instead: use `toReversed()`, `toSorted()` or `slice()`."

### লজিক: শুধু `<template>` ট্যাগে

চারটি অ্যাট্রিবিউট আছে: `for`, `if`, `else-if`, `else`। **এগুলো কাজ করে শুধু `<template>` ট্যাগে।** অন্য কোথাও এগুলো Alo-র কাছে সাধারণ HTML।

```html
<ul>
    <template for="post in data.blog">
        <li><a href="/blog/{{ post.slug }}/">{{ post.title }}</a></li>
    </template>
</ul>

<template for="(post, i) in data.blog">
    <Blog.PostCard post="{{ post }}" number="{{ i + 1 }}" />
</template>

<template if="stock > 10">
    <span>স্টকে আছে</span>
</template>
<template else-if="stock > 0">
    <span>মাত্র {{ stock }}টি বাকি</span>
</template>
<template else>
    <span>শেষ হয়ে গেছে</span>
</template>
```

**`<template>`-এর আচরণ:**

- লজিকওয়ালা `<template>` নিজে আউটপুটে যায় না; যায় শুধু ভেতরের কনটেন্ট। তাই মোড়ক ছাড়াই একাধিক এলিমেন্ট পুনরাবৃত্তি করা যায়।
- লজিকওয়ালা `<template>`-এ অন্য কোনো অ্যাট্রিবিউট থাকলে এরর, কারণ ট্যাগটি আউটপুটে যায় না: "This `<template>` is not part of the output, so `class` has no effect here." (ইঙ্গিত: "Put it on an element inside.")
- লজিক ছাড়া `<template>` সাধারণ HTML হিসেবে হুবহু আউটপুটে যায় (ব্যবহারকারীর নিজের JS-এর জন্য)। তবুও তার ভেতরের `{{ }}` আর কম্পোনেন্ট প্রসেস হয়।
- এই নিয়ম পেইজ, লেআউট আর কম্পোনেন্টের `<template>` ব্লকে, আর `<head>` ব্লকে, সব জায়গায় একই:

    ```html
    <head>
        <title>{{ item.title }}</title>
        <template if="item.image">
            <meta property="og:image" content="{{ item.image }}" />
        </template>
    </head>
    ```

**`for`:**

- লেখার ধরন দুটি: `x in list` আর `(x, i) in list`। `i` শূন্য থেকে শুরু হয়।
- মান অ্যারে না হলে এরর। অবজেক্টের ওপর লুপ চালাতে `Object.entries(obj)`।

**`if` / `else-if` / `else`:**

- একটি `if`, তারপর যতগুলো ইচ্ছা `else-if`, শেষে একটি ঐচ্ছিক `else`।
- এগুলো পাশাপাশি সিবলিং হতে হবে; মাঝে শুধু হোয়াইটস্পেস বা কমেন্ট চলবে। আগে `if` বা `else-if` ছাড়া `else-if` বা `else` এলে এরর।
- `else`-এ কোনো মান থাকলে এরর। `if` বা `else-if`-এ মান না থাকলে এরর।

**কড়া নিয়ম:**

- একই `<template>`-এ `for` আর `if` (বা লজিকের যেকোনো দুটি) একসাথে থাকলে এরর। নেস্ট করতে হবে:

    ```html
    <template for="post in data.blog">
        <template if="post.featured">
            <li>{{ post.title }}</li>
        </template>
    </template>
    ```

- কম্পোনেন্ট ট্যাগে `for`, `if`, `else-if` বা `else` থাকলে এরর:

    ```
    ✖ Error: pages/(site)/page.alo:8:3
      Logic can only be written on a <template> tag.

      Hint: <template for="post in data.blog">
              <Blog.PostCard post="{{ props.post }}" />
            </template>
    ```

- সাধারণ এলিমেন্টে `if`, `else-if` বা `else` থাকলে সতর্কবার্তা, কারণ এগুলো HTML-এর কোনো অ্যাট্রিবিউট নয়, তাই সম্ভবত ভুল: "`<li if>` will not work." (ইঙ্গিত: "Logic only works on `<template>`: wrap the element in `<template if>`.") `for` HTML-এর নিজের অ্যাট্রিবিউট (`<label for="email">`), তাই সেখানে সতর্কবার্তা দেবে শুধু তখন, যখন মানটি `x in y` ধাঁচের হয়।

### স্কোপের ভেরিয়েবল

| জায়গা       | ভেরিয়েবল                                                                          |
| ------------ | ---------------------------------------------------------------------------------- |
| page, layout | `data`, `route`, `base`, `item` (শুধু ডায়নামিক পেইজে), লুপ ভেরিয়েবল              |
| component    | `data`, `route`, `base`, `props` (পাঠানো সব প্রপ), লুপ ভেরিয়েবল                     |

- `route`: `{ path: "/blog/hello-world/" }`। base path ছাড়া পাথ।
- `base`: `--base` ফ্ল্যাগের মান, ডিফল্ট `"/"`। খুব কম দরকার হয়, কারণ base নিজে থেকে বসে (অংশ ১৪)।
- `item`: ডায়নামিক পেইজের বর্তমান আইটেম (অংশ ৯)।
- কম্পোনেন্ট `item` দেখে না; দরকার হলে প্রপ দিয়ে পাঠাতে হয়: `<Blog.PostMeta post="{{ item }}" />`।

## ৮. কম্পোনেন্ট

### নিয়ম দুটি

1. **বড় হাতের অক্ষর দিয়ে শুরু = কম্পোনেন্ট, ছোট হাতের অক্ষর দিয়ে শুরু = HTML।** এর কোনো ব্যতিক্রম নেই। `Header`, `Footer`, `Button`, `Form` স্বাভাবিক নামেই চলে।
2. **ফোল্ডার = ডট-যুক্ত নাম।** `components/blog/PostCard.alo` → `<Blog.PostCard />`। ফোল্ডারের নাম ছোট হাতের kebab-case, আর ট্যাগে PascalCase: `components/post-list/Item.alo` → `<PostList.Item />`। সব কম্পোনেন্ট সব জায়গায় (পেইজ, লেআউট, অন্য কম্পোনেন্ট) ব্যবহার করা যায়।

### খোঁজা ও যাচাই

- `components/` রিকার্সিভভাবে স্ক্যান হয়, আর প্রতিটি ফাইলের পূর্ণ ডট-যুক্ত নামের একটি ম্যাপ তৈরি হয়।
- ফাইলের নাম PascalCase না হলে এরর। ফোল্ডারের নাম kebab-case না হলে এরর।
- কম্পোনেন্ট না পেলে এরর, সাথে Levenshtein দিয়ে কাছাকাছি নাম: "Component `<Blog.PostLst>` not found." (ইঙ্গিত: "Did you mean `<Blog.PostList>`?")
- বড় হাতের অক্ষরে লেখা ট্যাগের নাম ছোট হাতের অক্ষরে কোনো HTML ট্যাগের সাথে মিললে (যেমন `<DIV>`), আর সেই নামে কোনো কম্পোনেন্ট না থাকলে, ইঙ্গিত: "For the HTML tag, write `<div>` in lowercase." এর জন্য HTML ট্যাগ নামের একটি তালিকা লাগবে, শুধু ইঙ্গিতের কাজে।
- সার্কুলার ডিপেন্ডেন্সিতে (`A → B → A`) পুরো চেইনসহ এরর।
- বিল্ড শেষে কোথাও ব্যবহার হয়নি এমন কম্পোনেন্টের তালিকা সতর্কবার্তা হিসেবে দেখাবে।

### প্রপস

```html
<Card
    title="হ্যালো"
    subtitle="পোস্ট: {{ post.title }}"
    post="{{ post }}"
    count="{{ 5 }}"
    featured
    post-date="আজ"
/>
```

- `title="হ্যালো"`: স্ট্রিং `"হ্যালো"`।
- `subtitle="পোস্ট: {{ post.title }}"`: মানের অংশে `{{ }}`, তাই সবসময় স্ট্রিং।
- `post="{{ post }}"`: **পুরো মান একটি `{{ }}` হলে আসল মানটিই যায়**, এখানে অবজেক্ট।
- `count="{{ 5 }}"`: সংখ্যা `5`। শুধু `count="5"` লিখলে যেত স্ট্রিং `"5"`।
- `featured`: মান ছাড়া, তাই `true`। `featured="{{ false }}"` দিলে `false`।
- `post-date="আজ"`: kebab-case নাম camelCase হয়ে যায়, `postDate`।

আরও নিয়ম:

- কম্পোনেন্টের ভেতরে প্রপ পড়া যায় শুধু `props` অবজেক্ট থেকে: `{{ props.title }}`, `{{ props.class }}`, `{{ props.post.slug }}`। প্রপের নাম আলাদা ভেরিয়েবল হয় না, তাই প্রপ কখনো লুপ ভেরিয়েবল, `data` বা JS-এর গ্লোবালের সাথে মেশে না।
- সব অ্যাট্রিবিউটই প্রপ। `class` বা `id` নিজে থেকে রুট এলিমেন্টে বসে না; কম্পোনেন্ট চাইলে নিজে বসায়: `class="card {{ props.class }}"`।
- না পাঠানো প্রপ `undefined`। ডিফল্ট মান: `{{ props.title ?? 'শিরোনাম নেই' }}`।
- প্রপের নামে কোনো নিষেধ নেই; `data` বা `item` নামের প্রপও শুধু `props.data`, `props.item`।
- **টাইপো ধরা:** পাঠানো প্রপ কম্পোনেন্টের কোনো এক্সপ্রেশনে `props.<নাম>` হিসেবে না থাকলে সতর্কবার্তা, সাথে কাছাকাছি নাম: "`<Card>` never uses `titel`." (ইঙ্গিত: "Did you mean `title`?") `class` আর `id`-এ এই সতর্কবার্তা আসে না। কম্পোনেন্ট `props`-কে সম্পূর্ণভাবে বা ডায়নামিকভাবে ব্যবহার করলে (`props[x]`, `{{ props }}`) এই যাচাই বন্ধ থাকে।
- **কোথা থেকে ডাকা হয়েছে:** কম্পোনেন্টের ভেতরে এরর হলে মেসেজে ডাকার জায়গাটিও থাকে: "`props.post` is `undefined`, so `.title` cannot be read.", সাথে "Called from: pages/(site)/page.alo:12"

### স্লট

- কম্পোনেন্ট ট্যাগের ভেতরের কনটেন্ট বসে কম্পোনেন্টের `<slot />`-এ।
- স্লট কনটেন্ট **প্যারেন্টের স্কোপে** রেন্ডার হয়, মানে প্যারেন্টের ভেরিয়েবল আর CSS স্কোপ অ্যাট্রিবিউট নিয়ে।
- ফলব্যাক কনটেন্ট সমর্থন করবে: `<slot>ফলব্যাক</slot>`।
- একটি কম্পোনেন্টে একটির বেশি `<slot>` থাকলে এরর। `<slot />` নেই কিন্তু কনটেন্ট দেওয়া হলে সতর্কবার্তা।
- লজিক ছাড়া সাধারণ HTML `<template>`-এর ভেতরে থাকা `<slot>` (Web Components-এর জন্য) Alo ছোঁয় না।

### উদাহরণ

```html
<!-- components/blog/PostCard.alo -->
<template>
    <Card class="post-card">
        <h3><a href="/blog/{{ props.post.slug }}/">{{ props.post.title }}</a></h3>
        <time>{{ props.post.date }}</time>
        <template if="props.post.tags">
            <ul class="tags">
                <template for="tag in props.post.tags"><li>{{ tag }}</li></template>
            </ul>
        </template>
    </Card>
</template>
```

## ৯. রাউটিং আর লেআউট

| সোর্স                                                                | আউটপুট                             | URL                  |
| -------------------------------------------------------------------- | ---------------------------------- | -------------------- |
| `pages/page.alo`                                                     | `dist/index.html`                  | `/`                  |
| `pages/about/page.alo`                                               | `dist/about/index.html`            | `/about/`            |
| `pages/(site)/about/page.alo`                                        | `dist/about/index.html`            | `/about/`            |
| `pages/blog/[slug]/page.alo` + `data/blog/2026-01-10-hello-world.md` | `dist/blog/hello-world/index.html` | `/blog/hello-world/` |
| `pages/not-found.alo`                                                | `dist/404.html`                    | —                    |

### নিয়ম

- `pages/`-এ `page.alo`, `layout.alo` আর `not-found.alo` ছাড়া অন্য কোনো `.alo` ফাইল থাকলে সতর্কবার্তা, সাথে ইঙ্গিত: "Put components in `components/`. …" অন্য এক্সটেনশনের ফাইলেও সতর্কবার্তা।
- ফোল্ডারের নাম হতে পারে: ছোট হাতের ইংরেজি অক্ষর, সংখ্যা আর হাইফেন; অথবা `[slug]`; অথবা `(name)` (রাউট গ্রুপ)। অন্য কিছু হলে এরর। `[id]`-এর মতো অন্য বন্ধনী-নামে এরর, সাথে ইঙ্গিত: "A dynamic folder is always named `[slug]`."
- `not-found.alo` থাকবে শুধু `pages/`-এর রুটে। অন্য কোথাও থাকলে সতর্কবার্তা দিয়ে উপেক্ষা।
- একই আউটপুট পাথ দুই জায়গা থেকে তৈরি হলে (যেমন দুই গ্রুপে `about/page.alo`, বা স্ট্যাটিক পেইজ আর কোনো আইটেমের slug মিলে গেলে) দুটি উৎসসহ এরর।
- `layout.alo` আছে কিন্তু তার নিচে কোনো `page.alo` নেই, তাহলে সতর্কবার্তা।

### ডায়নামিক পেইজ `[slug]`

**`pages/<পাথ>/[slug]/page.alo` প্রতিটি আইটেমের জন্য একটি পেইজ বানায় `data/<পাথ>/` অ্যারে ফোল্ডার থেকে।** এখানে `<পাথ>` হলো রাউট গ্রুপ বাদ দিয়ে পেইজের পাথ।

- `pages/(site)/blog/[slug]/page.alo` → `data/blog/`-এর প্রতিটি ফাইল।
- পেইজে বর্তমান আইটেম পাওয়া যায় `item`-এ, আর `item.slug` হলো URL-এর অংশ।
- একটি পাথে `[slug]` থাকতে পারে একবারই, আর সেটি শেষ সেগমেন্ট হতে হবে। না হলে এরর।
- ডেটা ফোল্ডার না থাকলে, খালি থাকলে বা অ্যারে না হলে এরর: "Add JSON or Markdown files to `data/blog/` for `pages/(site)/blog/[slug]/`."
- খসড়া আইটেমের পেইজ তৈরি হয় শুধু `dev`-এ।

### রাউট গ্রুপ `(name)`

- বন্ধনীর ফোল্ডার URL-এ গোনা হয় না, কিন্তু লেআউট খোঁজার পথে থাকে। তাই কিছু পেইজকে আলাদা লেআউট দেওয়া যায়, বা কোনো লেআউট ছাড়াই রাখা যায়।
- গ্রুপের ভেতরে গ্রুপ রাখা যায়।
- গ্রুপ ফোল্ডারে শুধু `layout.alo` রাখা যায়, `page.alo`-ও রাখা যায়। দ্বিতীয় ক্ষেত্রে পেইজের URL হয় গ্রুপের প্যারেন্টের URL।

### লেআউট নেস্টিং

পেইজের ফোল্ডার থেকে `pages/` রুট পর্যন্ত প্রতিটি ফোল্ডারে (গ্রুপসহ) `layout.alo` খোঁজা হয়। পেইজ প্রথমে বসে সবচেয়ে কাছের লেআউটের `<slot />`-এ, তারপর সেটি উপরেরটিতে, এভাবে রুট পর্যন্ত। কোনো ফোল্ডারে লেআউট না থাকলে সেই ধাপ বাদ যায়। `not-found.alo` শুধু `pages/layout.alo` পায় (থাকলে)।

### HTML শেল

```html
<!DOCTYPE html>
<html lang="{{ data.site?.lang ?? 'bn' }}">
    <head>
        <meta charset="UTF-8" />
        <meta name="viewport" content="width=device-width, initial-scale=1" />
        <title>...</title>
        <!-- মার্জ করা head -->
        <link rel="stylesheet" href="/assets/style.<hash>.css" />
    </head>
    <body>
        <!-- লেআউট + পেইজ -->
        <script src="/assets/global.<hash>.js"></script>
        <!-- global/ এ JS থাকলে -->
        <script src="/assets/components.<hash>.js"></script>
        <!-- পেইজে স্ক্রিপ্টওয়ালা কম্পোনেন্ট থাকলে -->
        <script src="/assets/pages/<route>.<hash>.js"></script>
        <!-- পেইজ/লেআউটে স্ক্রিপ্ট থাকলে -->
    </body>
</html>
```

হ্যাশ শুধু `build`-এ বসে। base path বসে অংশ ১৪ অনুযায়ী।

### head মার্জ

ক্রম: রুট লেআউট → ভেতরের লেআউট → পেইজ।

- `<title>`: শেষেরটি প্রাধান্য পায়। কোথাও না থাকলে `data.site.name`, সেটিও না থাকলে `"Alo"`।
- `<meta name>` / `<meta property>`: একই নাম হলে শেষেরটি প্রাধান্য পায়।
- ব্যবহারকারী `charset` বা `viewport` দিলে ডিফল্টটি বাদ যায়।
- বাকি সব ক্রম অনুযায়ী বসে; হুবহু ডুপ্লিকেট থাকলে একবারই বসে।

## ১০. ডেটা (`data/`)

### ফাইলের ধরন

- `.json`: পুরো ফাইলটিই মান।
- `.md`: YAML ফ্রন্ট ম্যাটার আর Markdown বডি। মান হয় `{ ...ফ্রন্ট ম্যাটার, body: "<HTML>" }` (অংশ ১১)।
- অন্য এক্সটেনশন থাকলে সতর্কবার্তা দিয়ে উপেক্ষা। একই নামে `.json` আর `.md` দুটিই থাকলে এরর।

### ডট-যুক্ত নাম (তিন নিয়ম)

1. **ফাইল = তার মান।** `data/team.json` → `data.team`।
2. **শুধু ফাইলে ভর্তি ফোল্ডার = অ্যারে।** `data/blog/` → `data.blog`। একই ফোল্ডারে JSON আর MD মেশানো যায়।
3. **সাবফোল্ডার আছে এমন ফোল্ডার = অবজেক্ট।** ভেতরের প্রতিটি ফাইল আর সাবফোল্ডার তার একটি key। `data/shop/products/` → `data.shop.products`। `data/` নিজে সবসময় অবজেক্ট।

এর সাথে:

- নামে `-` থাকলে key camelCase হয়: `footer-links.json` → `data.footerLinks`। নাম ছোট হাতের অক্ষর, সংখ্যা আর হাইফেন ছাড়া অন্য কিছু হলে এরর।
- একই ফোল্ডারে `blog.json` আর `blog/` দুটিই থাকলে এরর।

### অ্যারে ফোল্ডার (নিজে থেকে যা ঘটে)

- আইটেমগুলো **পূর্ণ ফাইলনাম অনুযায়ী** বর্ণানুক্রমে সাজানো থাকে। তারিখ দিয়ে নাম দিলে পুরনো থেকে নতুন ক্রমে আসে; সংখ্যা দিয়ে দিলে (`01-…`) ইচ্ছামতো ক্রম পাওয়া যায়।
- প্রতিটি আইটেম অবজেক্ট হতে হবে, না হলে এরর।
- **তারিখ:** নাম `YYYY-MM-DD-বাকি` ধাঁচের হলে তারিখটি `item.date` (স্ট্রিং, `"2026-01-10"`) হয়। তারিখ বৈধ না হলে এরর।
- **`slug`:** তারিখ বাদ দিয়ে ফাইলের নাম, এক্সটেনশন ছাড়া (`hello-world`)।
- ডেটায় আগে থেকে `slug` থাকলে এরর: "`slug` comes from the file name; remove it here." ফাইলনেমে তারিখ আছে আর ডেটাতেও `date` আছে, তাহলে এরর। ফাইলনেমে তারিখ না থাকলে ডেটার `date` চলবে।
- তারিখ বাদ দেওয়ার পর দুটি slug মিলে গেলে দুটি ফাইলের নামসহ এরর।
- `.md` ফাইলের ফ্রন্ট ম্যাটারে `body` থাকলে এরর।
- **খসড়া:** `"draft": true` থাকলে `build`-এ আইটেমটি বাদ যায়, আর তার পেইজও তৈরি হয় না। `dev`-এ সব দেখা যায়।

### সব জায়গায় পাওয়া যায়

`data` সব পেইজ, লেআউট আর কম্পোনেন্টে পাওয়া যায়। সাজাতে বা কাটতে সাধারণ JS লিখুন:

```html
<!-- হোমে সর্বশেষ ৩টি পোস্ট, নতুনটি আগে -->
<Blog.PostList posts="{{ data.blog.toReversed().slice(0, 3) }}" />
```

### অলস লোড আর অপরিবর্তনীয়তা

- কোনো ফাইল তখনই পড়া হয়, যখন কোনো টেমপ্লেট সেটি প্রথম পড়ে (Proxy-ভিত্তিক)। একবার পড়লে পুরো বিল্ডে ক্যাশ থাকে। Markdown বডি HTML-এ রূপান্তরিত হয় তখনই, যখন `body` প্রথম পড়া হয়।
- সব ডেটা deep-freeze করা থাকে। পরিবর্তনের চেষ্টায় এরর (অংশ ৭)।
- **ইমপ্লিমেন্টেশন নোট:** Proxy-র target নিজে freeze করবে না, কারণ frozen target-এ `get` trap অন্য মান ফেরত দিলে Proxy-র invariant ভাঙে। target থাকবে একটি খালি, freeze না করা অবজেক্ট; লোড হওয়া মানগুলো freeze হবে; আর `set`, `defineProperty`, `deleteProperty` trap সবসময় পরিষ্কার এরর দেবে। `ownKeys` আর `has` সঠিক key তালিকা দেবে, যাতে `Object.keys` আর `in` কাজ করে।
- JSON বা ফ্রন্ট ম্যাটার পার্স এররে ফাইলের নাম আর লাইন নম্বর থাকবে।

### সাইট সেটিংস

প্রচলিত জায়গা হলো `data/site.json`:

- `name`: ডিফল্ট title।
- `lang`: ডিফল্ট `bn`।
- `url`: সাইটের origin, যেমন `"https://example.com"`। sitemap-এর জন্য লাগে। এখানে পাথ অংশ থাকলে এরর: "`url` must be just the site origin.", সাথে ইঙ্গিত যে পাথ `--base` দিয়ে দিতে হবে।

বাকি ফিল্ড ব্যবহারকারী ইচ্ছামতো রাখতে পারে।

### ডায়নামিক পেইজের উদাহরণ

```html
<!-- pages/(site)/blog/[slug]/page.alo -->
<head>
    <title>{{ item.title }} | {{ data.site.name }}</title>
</head>
<template>
    <article>
        <h1>{{ item.title }}</h1>
        <time>{{ item.date }}</time>
        {{{ item.body }}}
    </article>
</template>
```

## ১১. Markdown কনটেন্ট

```markdown
---
title: হ্যালো ওয়ার্ল্ড
tags: [intro, news]
draft: false
---

# প্রথম পোস্ট

এটি **Markdown**-এ লেখা।
```

- ফ্রন্ট ম্যাটার ঐচ্ছিক। থাকলে ফাইলের একেবারে প্রথম লাইন হবে `---`, আর শেষ হবে পরের `---` লাইনে।
- ফলাফল `{ title, tags, draft, body }`। `body` হলো রেন্ডার করা HTML; টেমপ্লেটে বসাতে `{{{ item.body }}}`।
- Markdown-এর ভেতরে `{{ }}` প্রসেস হয় **না**; কনটেন্ট শুধু ডেটা।
- Markdown ব্যবহারকারীর নিজের লেখা, তাই raw HTML হুবহু যায় (স্যানিটাইজ করা হয় না)। README-তে এটি বলা থাকবে।

### YAML সাবসেট (`core/yaml.js`)

শুধু এগুলো সমর্থিত:

- `key: value`। key যেমন লেখা তেমন থাকে।
- স্কেলার মান:
    - কোট ছাড়া স্ট্রিং, `'সিঙ্গেল'` বা `"ডাবল"` কোটে স্ট্রিং (ডাবল কোটে `\"`, `\\`, `\n` এস্কেপ চলবে)।
    - সংখ্যা।
    - `true` / `false`, আর `null` / `~`।
    - তারিখের মতো মান স্ট্রিংই থাকে।
- ইনলাইন লিস্ট `[a, b, "c d"]`, আর ব্লক লিস্ট (`- মান`), দুটিই শুধু স্কেলার দিয়ে।
- `#` দিয়ে কমেন্ট (কোটের বাইরে থাকলে)।
- খালি লাইন।

অন্য কিছু (নেস্টেড অবজেক্ট, `|` বা `>` দিয়ে মাল্টিলাইন, anchor, tab দিয়ে indent) থাকলে লাইন নম্বরসহ এরর, সাথে ইঙ্গিত: "Use a `.json` file for complex data." একই key দুবার থাকলে এরর।

### Markdown সাবসেট (`core/markdown.js`)

CommonMark-এর কাছাকাছি, সাথে GFM-এর কয়েকটি বৈশিষ্ট্য:

| ধরন    | সমর্থন                                                                                                                                                         |
| ------ | --------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| ব্লক   | ATX আর setext হেডিং, প্যারাগ্রাফ, blockquote, ক্রমযুক্ত আর ক্রমহীন লিস্ট (নেস্টেড), fenced কোড (ভাষাসহ), indented কোড, thematic break, GFM টেবিল, raw HTML ব্লক |
| ইনলাইন | `*em*`, `**strong**`, `~~del~~`, `` `code` ``, লিংক, ছবি, `<autolink>`, backslash এস্কেপ, hard line break, ইনলাইন HTML, HTML entity                             |
| আউটপুট | হেডিংয়ে নিজে থেকে `id` (বাংলা অক্ষর রেখে; ডুপ্লিকেট হলে `-2`); কোডে `<pre><code class="language-js">` (হাইলাইটিং নেই)                                          |
| নেই    | reference-style লিংক, footnote, task list, ইমোজি শর্টকোড, math। এগুলো আক্ষরিক লেখা হিসেবে আসে।                                                                  |

- `/` দিয়ে শুরু হওয়া লিংক আর ছবিতে base path নিজে থেকে বসে (অংশ ১৪)।
- টেস্টের জন্য CommonMark spec-এর সমর্থিত অংশের উদাহরণ ফিক্সচার হিসেবে রাখা হবে (spec-এর ডেটা ফাইল, কোনো লাইব্রেরি নয়)।

## ১২. CSS

### স্কোপড CSS (ডিফল্ট)

- প্রতিটি `.alo` ফাইলের একটি স্কোপ আইডি থাকে: প্রজেক্ট-আপেক্ষিক পাথের SHA-1 হ্যাশের প্রথম ৬ অক্ষর। অ্যাট্রিবিউট হয় `data-a-<id>`।
- ওই ফাইলের `<template>` থেকে আসা প্রতিটি এলিমেন্টে অ্যাট্রিবিউটটি বসে; স্লট কনটেন্ট পায় প্যারেন্টেরটি।
- কমা দিয়ে আলাদা প্রতিটি সিলেক্টরের **শেষ compound selector-এ** `[data-a-<id>]` বসে:
    - `.card h2` → `.card h2[data-a-a1b2c3]`
    - `.btn:hover` → `.btn[data-a-a1b2c3]:hover`
    - `.card::before` → `.card[data-a-a1b2c3]::before`
    - `a, b` → `a[data-a-a1b2c3], b[data-a-a1b2c3]`
- `@media`, `@supports`, `@container` আর `@layer`-এর ভেতরে রিকার্সিভভাবে রিরাইট হয়। `@keyframes`, `@font-face`, `@import` আর `@charset` অপরিবর্তিত থাকে।
- একটি ছোট নিজস্ব CSS পার্সার লাগবে, যা কমেন্ট, স্ট্রিং আর নেস্টেড ব্লক সামলায়। এই পার্সারই মিনিফায়ারও ব্যবহার করবে।
- **চাইল্ড কম্পোনেন্টের রুট:** এটি শুধু চাইল্ডের নিজের স্কোপ অ্যাট্রিবিউট পায়। প্যারেন্ট থেকে স্টাইল করতে `class` প্রপ পাঠান (`<Card class="mt-4" />`, আর Card-এ `class="card {{ props.class }}"`)। বাকি ক্ষেত্রে `<style global>`।

### গ্লোবাল CSS

- `<style global>` হুবহু যায়।
- `global/` ফোল্ডারের সব `*.css` (সাবফোল্ডারসহ) **প্রজেক্ট-আপেক্ষিক পূর্ণ পাথের বর্ণানুক্রমে** জোড়া হয়, স্কোপ ছাড়া।

### আউটপুট

- `dist/assets/style.<hash>.css`: আগে `global/`-এর CSS, তারপর ব্যবহৃত সব `.alo` ফাইলের CSS (প্রতিটি একবার)। dev-এ উৎসের কমেন্টসহ, build-এ মিনিফাই করা।
- অব্যবহৃত কম্পোনেন্টের CSS আউটপুটে যায় না।

## ১৩. JavaScript

### `global/` JS

- সব `*.js` (সাবফোল্ডারসহ) পূর্ণ পাথের বর্ণানুক্রমে জোড়া হয়, **IIFE ছাড়া**, যাতে ব্যবহারকারী গ্লোবাল ফাংশন বানাতে পারে। মাঝে `;\n` আর উৎস ফাইলের কমেন্ট থাকে। আউটপুট `dist/assets/global.<hash>.js`।
- `global/`-এ `.css` আর `.js` ছাড়া অন্য ফাইল থাকলে সতর্কবার্তা, সাথে ইঙ্গিত: "Put JSON data in `data/`, and images or fonts in `public/`."

### কম্পোনেন্ট স্ক্রিপ্ট

- প্রতিটি ইনস্ট্যান্সের জন্য আলাদা করে চলে। পাওয়া যায় `$el`, মানে কম্পোনেন্টের রুট এলিমেন্ট।
- একাধিক রুট এলিমেন্ট থাকলে `$el` হয় প্রথমটি, সাথে সতর্কবার্তা।
- **বিল্ডের ডেটা JS-এ পাঠাতে সাধারণ HTML-এর `data-*` অ্যাট্রিবিউট ব্যবহার হয়:**

    ```html
    <template>
        <div class="counter" data-start="{{ props.start ?? 0 }}">
            <button>+</button> <span></span>
        </div>
    </template>

    <script>
        let n = Number($el.dataset.start);
        const span = $el.querySelector('span');
        span.textContent = n;
        $el.querySelector('button').addEventListener('click', () => {
            span.textContent = ++n;
        });
    </script>
    ```

- স্ক্রিপ্ট থাকলে রুট এলিমেন্টে বসে `data-a-c="<পূর্ণ ডট-যুক্ত নাম>"`। স্ক্রিপ্ট না থাকলে বসে না।
- `dist/assets/components.<hash>.js`:

    ```js
    // ধারণা, হুবহু নয়
    const __a = {
        Counter: function ($el) {
            /* ব্যবহারকারীর কোড */
        },
    };
    document.querySelectorAll('[data-a-c]').forEach((el) => {
        const fn = __a[el.dataset.aC];
        if (fn) {
            try {
                fn(el);
            } catch (e) {
                console.error('[alo] ' + el.dataset.aC + ':', e);
            }
        }
    });
    ```

- একটি কম্পোনেন্টের এরর অন্যগুলো থামায় না।

### page আর layout স্ক্রিপ্ট

- রুট লেআউট আগে, তারপর ক্রম অনুযায়ী, সব একটি ফাইলে: `dist/assets/pages/<route-name>.<hash>.js`। নামকরণ: `/` → `index`, `/about/` → `about`। ডায়নামিক পেইজের সব আইটেম একটিই ফাইল ব্যবহার করে (`blog__slug`)।
- প্রতিটি ফাইলের কোড আলাদা IIFE-তে থাকে। এখানে `$el` নেই।

### base path আর JS

ব্যবহারকারীর JS-এর স্ট্রিং রিরাইট করা হয় না। `--base` দিলে `<html>` ট্যাগে `data-base="/repo/"` বসে। JS থেকে পড়া যায় `document.documentElement.dataset.base ?? '/'` দিয়ে।

### ইন্টারঅ্যাকটিভিটি (README-তে যেভাবে শেখানো হবে)

- ক্লিক, মেনু, ট্যাব, মোডাল, ফর্ম: `$el` + `addEventListener`।
- বিল্ডের ডেটা JS-এ নেওয়া: `data-*` + `$el.dataset`।
- কম্পোনেন্টের মধ্যে যোগাযোগ: `document.dispatchEvent(new CustomEvent('cart:add'))` আর `addEventListener`।
- পেইজ বদলালেও মান ধরে রাখা: `localStorage`।
- আরও বেশি লাগলে: একটি `<script>` দিয়ে Alpine.js যোগ করুন। Alo তার অ্যাট্রিবিউট বদলায় না।

## ১৪. প্রোডাকশন আউটপুট (নিজে থেকে হয়)

এই অংশের কিছুই ব্যবহারকারীকে শিখতে হয় না। base path ছাড়া সবকিছু শুধু `build`-এ চলে। `dev` সবসময় পড়ার মতো, হ্যাশ ছাড়া আর মিনিফাই না করা আউটপুট দেয়।

### base path (`--base`)

```bash
node alo build --base /my-repo/
node alo dev --base /my-repo/
```

- মান স্বাভাবিক করা হয়: শুরু আর শেষে `/` থাকবে (`my-repo` → `/my-repo/`)। অননুমোদিত অক্ষর থাকলে এরর। ডিফল্ট `/`।
- টেমপ্লেটে ব্যবহারকারী সবসময় লেখে `href="/about/"`। **রেন্ডার শেষে** চূড়ান্ত HTML-এ নিচের জায়গাগুলোতে `/` দিয়ে শুরু হওয়া (কিন্তু `//` নয়) মানের সামনে base বসে:
    - অ্যাট্রিবিউট: `href`, `src`, `action`, `formaction`, `poster`, `<object>`-এর `data`, `xlink:href`, `srcset` আর `imagesrcset` (প্রতিটি URL)।
    - `<meta http-equiv="refresh">`-এর `url=`।
    - ইনলাইন `style`-এর `url(/...)`।
- CSS ফাইলের `url(/...)`-এও base বসে।
- `route.path`-এ base থাকে না, তাই মেনুর সক্রিয় লিংক মেলানো (`route.path === link.href`) সবসময় কাজ করে।
- dev সার্ভার `--base` পেলে সাইটটি সেই পাথের নিচে সার্ভ করে, আর `/`-এ গেলে base-এ redirect করে।

### ফাইলনেমে হ্যাশ

- `dist/assets/`-এর সব তৈরি করা ফাইলে হ্যাশ বসে: `style.<h>.css`, `global.<h>.js`, `components.<h>.js`, `pages/<route>.<h>.js`। এখানে `<h>` হলো চূড়ান্ত কনটেন্টের SHA-256-এর প্রথম ৮ hex অক্ষর।
- `public/`-এর ফাইলে হ্যাশ বসে না।

### CSS মিনিফাই

- অংশ ১২-এর CSS পার্সার দিয়ে কমেন্ট সরানো হবে (`/*! … */` থাকবে), হোয়াইটস্পেস সংকুচিত হবে, আর `}`-এর আগের শেষ `;` সরবে। স্ট্রিং, `url()` আর কাস্টম প্রপার্টির মান হুবহু থাকবে।
- JS আর HTML মিনিফাই হবে না। JS-এর জন্য নিরাপদ মিনিফায়ার বানাতে একটি পূর্ণ JS পার্সার লাগে, অথচ ছোট সাইটে লাভ সামান্য। HTML-এর হোয়াইটস্পেস হুবহু রাখতে হয়।

### `sitemap.xml`

- `data.site.url` থাকলে তৈরি হয়। না থাকলে সতর্কবার্তা: "Add `url` to `data/site.json` to get a sitemap.xml."
- তাতে থাকে সব HTML পেইজ, শুধু `404.html` আর যে পেইজের head-এ `<meta name="robots" content="noindex…">` আছে সেগুলো বাদে।
- URL হয় `site.url` + base + `route.path`। `<lastmod>` থাকে না।

### `robots.txt`

- `public/robots.txt` না থাকলে তৈরি হয়: `User-agent: *`, `Allow: /`, আর `site.url` থাকলে `Sitemap: …`।
- `public/`-এ `robots.txt` বা `sitemap.xml` থাকলে সেটিই যায়, আর সেই ফাইল তৈরি হয় না।

## ১৫. বিল্ড প্রসেস

1. Node-এর ভার্সন যাচাই; একটি অস্থায়ী আউটপুট ফোল্ডার তৈরি।
2. `global/` স্ক্যান।
3. `components/` স্ক্যান: ডট-যুক্ত নামের ম্যাপ তৈরি, নাম যাচাই।
4. `data/` স্ক্যান: কাঠামো, নাম, তারিখ আর slug। কনটেন্ট পড়া হয় পরে, অলসভাবে।
5. `pages/` স্ক্যান: রাউট তালিকা, গ্রুপ আর লেআউট চেইন। `[slug]`-এর জন্য ডেটা অ্যারে পড়া (খসড়া বাদ যায় শুধু `build`-এ)। আউটপুট পাথের সংঘর্ষ যাচাই।
6. প্রতিটি `.alo` একবারই পার্স হয়, তারপর ক্যাশ থেকে আসে।
7. প্রতিটি রাউটের জন্য:
    - স্কোপ তৈরি।
    - রেন্ডার: কম্পোনেন্ট, প্রপস, স্লট, `for`/`if`, ইন্টারপোলেশন, স্কোপ অ্যাট্রিবিউট।
    - লেআউটে মোড়ানো, head মার্জ, HTML শেল।
    - base path বসানো।
8. CSS আর JS তৈরি → (build-এ) CSS মিনিফাই → হ্যাশ → HTML-এ লিংক বসানো → (build-এ) sitemap আর robots।
9. `public/` কপি। তৈরি হওয়া ফাইলের সাথে নাম মিললে এরর, শুধু অংশ ১৪-এর ব্যতিক্রম ছাড়া।
10. সফল হলে অস্থায়ী ফোল্ডারের নাম বদলে `dist/` করা হয়।
11. সারাংশ দেখানো: পেইজ সংখ্যা, সময়, সতর্কবার্তা, অব্যবহৃত কম্পোনেন্ট।

এরর হলে বিল্ড থামে, আগের `dist/` অক্ষত থাকে, আর exit code হয় `1`।

core অংশ (ধাপ ২–৮) ডিস্কে লেখে না। একটি ছোট ফাইল-রিডার ইন্টারফেস দিয়ে ইনপুট নেয় `{ reader, mode: 'dev' | 'build', base }` আকারে, আর আউটপুট দেয় `{ path, contents }`-এর তালিকা।

## ১৬. এরর আর সতর্কবার্তা

`AloError` ক্লাসের ফিল্ড: `{ file, line, column, message, hint, calledFrom? }`।

```
✖ Error: pages/(site)/about/page.alo:12:5
  Component `<Crad>` not found.

  11 |   <h1>আমাদের সম্পর্কে</h1>
  12 |   <Crad title="মিশন" />
     |   ^
  13 | </template>

  Hint: Did you mean `<Card>`? (components/Card.alo)
```

- টার্মিনাল আর ব্রাউজারের এরর ওভারলে, দুই জায়গাতেই সব মেসেজ ইংরেজিতে।
- কম্পোনেন্টের ভেতরের এররে `calledFrom` থাকে, আর মেসেজে "Called from: …" লাইন দেখায়।
- সতর্কবার্তা হলুদ `⚠`, এরর লাল `✖` (ANSI রঙে)। `NO_COLOR` সেট করা থাকলে রঙ বন্ধ।
- dev মোডে বিল্ড এরর হলে ব্রাউজারে একই তথ্যসহ একটি এরর ওভারলে দেখায়। ঠিক করে সংরক্ষণ করলে পেইজ নিজে থেকে রিলোড হয়।

## ১৭. CLI

```bash
alo init [folder]                # উদাহরণসহ নতুন প্রজেক্ট (npx @msilabs/alo init)
alo dev [--port 3000] [--base /] # dev সার্ভার + লাইভ রিলোড
alo build [--base /]             # dist/ এ প্রোডাকশন বিল্ড
alo new page blog/first-post     # pages/blog/first-post/page.alo
alo new page "(bare)/launch"     # pages/(bare)/launch/page.alo
alo new layout blog              # pages/blog/layout.alo
alo new component Card           # components/Card.alo
alo new component blog/PostCard  # components/blog/PostCard.alo
alo new post blog/hello-world    # data/blog/<আজকের তারিখ>-hello-world.md
alo --help / --version
```

- `init` এমন ফোল্ডারে চলবে না যেটি ফাঁকা নয়।
- `new` আগে থেকে থাকা ফাইল ওভাররাইট করবে না। কম্পোনেন্টের নাম PascalCase না হলে এরর।
- `new post` ফ্রন্ট ম্যাটারে `title` আর `draft: true` বসিয়ে একটি Markdown ফাইল বানায়।
- অজানা কমান্ডে সাহায্য দেখায়, সাথে কাছাকাছি কমান্ডের পরামর্শ।
- `--port` আর `--base` ছাড়া আর কোনো ফ্ল্যাগ নেই।
- প্যাকেজের `package.json`-এ থাকবে `"bin": { "alo": "bin/alo.js" }` আর `"exports": { "./cli": "./cli/index.js" }`।

### dev সার্ভার

- Node-এর `http` দিয়ে চলে। ডিফল্ট পোর্ট ৩০০০; ব্যস্ত থাকলে পরেরটি নেয়, আর সেটি জানিয়ে দেয়।
- `.alo/dev/` অস্থায়ী ফোল্ডারে বিল্ড করে সেখান থেকে সার্ভ করে। খসড়া আইটেম দেখা যায়।
- পরিষ্কার URL: `/about` থেকে `/about/`-এ redirect, `/about/` সার্ভ করে `about/index.html`। কিছু না পেলে `404.html` (থাকলে), স্ট্যাটাস ৪০৪ সহ।
- সঠিক Content-Type দেয়: html, css, js, json, xml, svg, png, jpg, webp, avif, gif, ico, woff2, woff, ttf, mp4, webm, txt, pdf।
- `pages/`, `components/`, `data/`, `global/` আর `public/` রিকার্সিভভাবে `fs.watch` দিয়ে দেখা হয়, ১০০ms debounce সহ।
- **রিবিল্ড:** প্রতিবার পুরো সাইট রিবিল্ড হয়। পার্স ক্যাশ, ডেটা ক্যাশ আর Markdown ক্যাশ বাতিল হয় শুধু বদলানো ফাইলগুলোর জন্য। কোন ডেটা কোন পেইজে লাগে, তা ট্র্যাক করা হবে না।
- লাইভ রিলোড চলে Server-Sent Events দিয়ে, `<base>__alo/reload` পাথে। dev মোডে প্রতিটি HTML-এর শেষে একটি ছোট স্ক্রিপ্ট ইনজেক্ট হয়; প্রোডাকশনে হয় না।

## ১৯. উদাহরণ সাইট (`example/` আর `init` টেমপ্লেট)

`example/` হলো Alo-র নিজের ওয়েবসাইট, আসল বাংলা কনটেন্ট আর পেশাদার ডিজাইনসহ। প্রতিটি ফিচার সেখানে অন্তত একবার স্বাভাবিক ব্যবহারে আছে। `init` টেমপ্লেট এর একটি ছোট সংস্করণ, একই ডিজাইনে: হোম, About, Markdown ব্লগ, Header, Footer, Card।

- `pages/layout.alo`: সব পেইজের `<head>` (ফন্ট, favicon, বর্ণনা)। `(site)` গ্রুপের লেআউটে Header আর Footer, আর ব্লগের জন্য নেস্টেড লেআউট।
- `(bare)` গ্রুপে লেআউট ছাড়া একটি `launch` পেইজ, যাতে `noindex` মেটা আছে।
- হোম, শুরু করার গাইড (`/docs/`), "কেন আলো" (`/about/`), ব্লগ তালিকা, 404।
- ব্লগে ৫টি Markdown পোস্ট, প্রতি শুক্রবার একটি, আর শেষটিতে `draft: true`; তারিখ দেখায় বাংলায়।
- `Header`: `data.menu` থেকে `<template for>` দিয়ে মেনু, `route.path` দিয়ে সক্রিয় লিংক, মোবাইল মেনুর জন্য `$el` স্ক্রিপ্ট।
- `Logo`: ইনলাইন SVG (কেসসহ `radialGradient`), প্রতিটি জায়গায় আলাদা `id`-এর জন্য প্রপ।
- `Card`: প্রপস, `class` প্রপ, স্লট, স্কোপড CSS।
- `Feature`: `data/features.json`-এর প্রতিটি ফিচার; আইকন আর অবস্থার ব্যাজ (`চালু` / `পরীক্ষামূলক` / `আসছে`) `if` / `else-if` / `else` দিয়ে।
- `Blog.PostCard`, `Blog.PostList`; হোমে `Blog.PostList` দিয়ে সর্বশেষ ৩টি পোস্ট।
- `Faq`: `data/faq.json` থেকে; ক্লিকে খোলে আর বন্ধ হয়।
- `Counter`: `data-*` দিয়ে বিল্ডের মান নিয়ে JS চালায়।
- কোডের উদাহরণে `\{{` দিয়ে আক্ষরিক `{{ }}`; Markdown বডির স্টাইলের জন্য `<style global>`।
- `data/site.json` (`url` সহ), `data/menu.json`, `data/features.json`, `data/faq.json`।
- `global/base/01-reset.css`, `global/theme.css` (রঙ, ফন্ট, ডার্ক মোড), `global/main.js`।
- `public/`-এ favicon আর একটি SVG।

**উদাহরণ সাইটটিই স্বীকৃতি টেস্ট।** মাইলস্টোন ২ থেকে প্রতিটি ধাপে `example/`-এ সেই ধাপের ফিচার যোগ হবে, আর end-to-end টেস্ট তার আউটপুট যাচাই করবে।

### FAQ-তে অবশ্যই থাকবে

> **`<template if>` আর `<template for>` কি ব্রাউজারে চলে?**
>
> না। এগুলো চলে **বিল্ডের সময়, একবার**। Alo এগুলো দিয়ে HTML ফাইল তৈরি করে, তারপর এগুলোর আর অস্তিত্ব থাকে না; ব্রাউজার পায় শুধু তৈরি হওয়া HTML। ক্লিকে বা ইনপুটে যা বদলাবে, সেটি লিখুন কম্পোনেন্টের `<script>`-এ।

> **`<li if>` বা `<Card for>` কেন চলে না?**
>
> লজিক থাকে শুধু `<template>` ট্যাগে। তাই ফাইলে দেখেই বোঝা যায় কোথায় বিল্ডের সময় কিছু ঘটবে, আর বাকি সব খাঁটি HTML থাকে।

> **লজিকের জন্য আলাদা কোনো সিনট্যাক্স নেই কেন?**
>
> যাতে প্রতিটি `.alo` ফাইল সাধারণ HTML থাকে: এডিটর ঠিকমতো রঙ করে, আর HTML জানা যে কেউ পড়তে পারে।

> **কম্পোনেন্টের প্রপ JS-এ কীভাবে পাব?**
>
> সাধারণ HTML-এর মতো: `data-count="{{ props.count }}"` লিখুন, আর JS-এ পড়ুন `$el.dataset.count` দিয়ে।

> **কনফিগারেশন ফাইল নেই, তাহলে GitHub Pages-এর সাব-পাথ কীভাবে দেব?**
>
> `node alo build --base /repo-name/`। লিংক সবসময় `/about/`-এর মতো লিখুন; বাকি অংশ Alo নিজে বসায়।

## ২২. টেস্ট

`node --test` দিয়ে, কোনো টেস্ট লাইব্রেরি ছাড়া। CI-তে Node 22, 24, 26 × Linux, Windows, আর macOS-এ Node 24 (`DECISIONS.md` #২৬)। ন্যূনতম যা টেস্ট হবে:

- **html-parser:** কেস অক্ষুণ্ণ থাকা, ডট-যুক্ত ট্যাগ নাম, void আর self-closing, raw text, অ্যাট্রিবিউটের চার ধরন, `:click`/`@click`/`x-data` হুবহু থাকা, কমেন্ট, লাইন নম্বর, বন্ধ না করা ট্যাগ, `{{ a > b }}`, কোটের ভেতরে কোটওয়ালা এক্সপ্রেশন, স্ট্রিংয়ের ভেতরে `}}`, বন্ধ না করা `{{`।
- **sfc:** ব্লক ভাগ, ডুপ্লিকেট এরর, কম্পোনেন্টে `<head>` এরর, লেআউটে `<slot />`-এর সংখ্যা, টপ-লেভেল ব্লকে অ্যাট্রিবিউট থাকলে এরর।
- **expression:** এস্কেপ, raw, `null`/`undefined`, `\{{`, ReferenceError মেসেজ, freeze করা ডেটায় মেথড দিয়ে আর সরাসরি মান বসিয়ে বদলানোর চেষ্টায় এরর।
- **attributes:** পুরো-মান `{{ }}`-এ `null` হলে অ্যাট্রিবিউট বাদ; বুলিয়ান অ্যাট্রিবিউটে সত্য আর মিথ্যা; সাধারণ অ্যাট্রিবিউটে `false` থেকে `"false"`; অংশ-মানে সবসময় স্ট্রিং; অ্যাট্রিবিউটে `{{{ }}}` থাকলে এরর।
- **template লজিক:**
    - `for` (ইনডেক্সসহ), অ্যারে না হলে এরর।
    - `if` / `else-if` / `else` চেইন, একাধিক `else-if`।
    - আগে `if` ছাড়া `else-if` বা `else`; `else`-এ মান; `if`-এ মান না থাকা — সব ক্ষেত্রে এরর।
    - একই ট্যাগে দুটি লজিক থাকলে এরর।
    - লজিকওয়ালা `<template>`-এ অন্য অ্যাট্রিবিউট থাকলে এরর।
    - কম্পোনেন্ট ট্যাগে লজিক থাকলে এরর আর ইঙ্গিত।
    - `<li if>`-এ সতর্কবার্তা; `<label for="x">`-এ সতর্কবার্তা নেই; `<div for="x in y">`-এ সতর্কবার্তা।
    - মোড়ক ছাড়া একাধিক এলিমেন্ট আউটপুট; লজিক ছাড়া `<template>` হুবহু থাকা; `<head>`-এ `<template if>`।
- **render:** প্রপস (স্ট্রিং, পুরো-মান `{{ }}`-এ আসল মান, অংশ-মানে স্ট্রিং, বুলিয়ান, kebab→camel, শুধু `props` দিয়ে পড়া, না পাঠানো প্রপ `undefined`); স্লট আর ফলব্যাক; স্লট প্যারেন্টের স্কোপে; একাধিক `<slot>` থাকলে এরর; নেস্টেড কম্পোনেন্ট; সার্কুলার এরর; এররে `calledFrom`।
- **components:** ডট-যুক্ত নাম, kebab ফোল্ডার থেকে PascalCase, অজানা নামের পরামর্শ, `<DIV>` ইঙ্গিত, অব্যবহৃত কম্পোনেন্টের তালিকা, প্রপের টাইপোতে সতর্কবার্তা (আর `props[x]` থাকলে বন্ধ)।
- **data:**
    - ফাইল/অ্যারে/অবজেক্ট ম্যাপিং; JSON আর MD মেশানো; camelCase।
    - `blog.json` + `blog/` আর `x.json` + `x.md` সংঘর্ষ।
    - ফাইলনেম অনুযায়ী ক্রম; তারিখ বাদ দিয়ে slug; `item.date`; অবৈধ তারিখ; slug সংঘর্ষ; `date` দুই জায়গায় থাকলে এরর; অটো `slug` আর ডেটার `slug` সংঘর্ষ।
    - খসড়া build-এ বাদ আর dev-এ থাকে।
    - অলস লোড (না পড়া ফাইল খোলা হয় না, `body` না পড়লে Markdown রেন্ডার হয় না)।
    - Proxy-তে `Object.keys`, `in` আর মান বসানোর চেষ্টায় এরর।
    - JSON এররের লাইন।
- **yaml:** সব সমর্থিত ধরন; অসমর্থিত গঠনে লাইনসহ এরর আর ইঙ্গিত; ডুপ্লিকেট key; কোটের ভেতরে `#`।
- **markdown:** CommonMark ফিক্সচার (সমর্থিত অংশ); GFM টেবিল আর strikethrough; বাংলা হেডিংয়ে `id`; raw HTML; ভেতরে `{{` আক্ষরিক থাকে।
- **routes:** স্ট্যাটিক আর `[slug]` ম্যাপিং; রাউট গ্রুপ URL-এ যায় না; গ্রুপ লেআউট; লেআউট চেইন; `[id]`-এ এরর আর ইঙ্গিত; মাঝখানে `[slug]` থাকলে এরর; ডেটা ফোল্ডার না থাকলে এরর; আউটপুট সংঘর্ষ; অবৈধ ফোল্ডার নাম; `pages/` না থাকলে এরর; `not-found`-এর অবস্থান।
- **css:** অংশ ১২-এর সব উদাহরণ; `@media`; `@keyframes`; কমেন্ট আর স্ট্রিংয়ে `{`; `global/` সাবফোল্ডারের ক্রম; মিনিফাই করলে স্ট্রিং, `url()` আর `/*! */` অক্ষত থাকে।
- **base-path:** সব অ্যাট্রিবিউটে, `srcset`-এ আর CSS `url()`-এ বসে; `//cdn…` আর `https://…` অক্ষত থাকে; `route.path`-এ base থাকে না; `data-base`; মান স্বাভাবিক করা।
- **hash:** কনটেন্ট বদলালে হ্যাশ বদলায়; HTML-এ সঠিক নাম বসে; dev-এ হ্যাশ থাকে না।
- **seo:** `site.url` থাকলে আর না থাকলে; `noindex` বাদ যায়; base-সহ absolute URL; `public/robots.txt` থাকলে সেটিই যায়; `site.url`-এ পাথ থাকলে এরর।
- **head:** title আর meta মার্জ, `data.site.name` ডিফল্ট।
- **compile:** core কোনো ডিস্কে না লিখে আউটপুটের তালিকা দেয়।
- **end-to-end:**
    - `example/` বিল্ড করে আউটপুট আর মূল কনটেন্ট যাচাই।
    - একই সাইট `--base /repo/` দিয়ে বিল্ড করে সব লিংক যাচাই।
    - `init` করা নতুন প্রজেক্ট এরর ছাড়া বিল্ড হয়।
    - `npm install` ছাড়া রুটের `alo` ফাইল চালালে সঠিক মেসেজ।
    - Node-এর ভার্সন কম হলে সঠিক মেসেজ।

## ২৩. কাজের ধাপ (মাইলস্টোন)

প্রতিটি ধাপ শেষে টেস্ট পাস হতে হবে, `example/`-এ সেই ধাপের ফিচার যোগ হতে হবে, তারপর পরের ধাপ।

1. **ভিত্তি:** `package.json` (engines `>=22`), CLI কাঠামো (`--help`, `--version`, ভার্সন যাচাই), `errors.js`, `log.js`, CI ম্যাট্রিক্স, অংশ ২৫ দিয়ে `DECISIONS.md` শুরু।
2. **সরু end-to-end পথ:** ন্যূনতম পার্সার, `sfc`, লেখায় `{{ }}`, `compile` + `build`। লক্ষ্য `example/pages/page.alo` থেকে `dist/index.html`। প্রথম end-to-end টেস্ট এখানেই লেখা হবে।
3. **পার্সার পূর্ণ করা:** `html-parser.js` (অংশ ৬-এর সব) আর `sfc.js`।
4. **টেমপ্লেট:** `expression.js`, `attributes.js`, `<template>` লজিক (`for`, `if`/`else-if`/`else`, সব এরর আর সতর্কবার্তা)।
5. **কম্পোনেন্ট:** স্ক্যান, ডট-যুক্ত নাম, প্রপস, স্লট, সার্কুলার ডিটেকশন, পরামর্শ, প্রপের টাইপো, `calledFrom`।
6. **রাউটিং আর লেআউট:** `routes.js`, রাউট গ্রুপ, নেস্টিং, HTML শেল, `head.js`, not-found।
7. **ডেটা:** `data.js` (ডট-যুক্ত নাম, অলস Proxy, freeze, খসড়া, তারিখ/slug), `[slug]` রাউট।
8. **Markdown:** `yaml.js`, `markdown.js`, CommonMark ফিক্সচার।
9. **CSS:** `css-parser.js`, স্কোপিং, `<style global>`, `global/` CSS, `style.css`।
10. **JS:** কম্পোনেন্ট স্ক্রিপ্ট আর `$el`, `components.js`, page/layout স্ক্রিপ্ট, `global.js`।
11. **প্রোডাকশন আউটপুট:** `base-path.js`, হ্যাশ, `css-minify.js`, `seo.js`।
12. **বিল্ড পূর্ণতা:** `public/` কপি, অস্থায়ী ফোল্ডারে বিল্ড, সারাংশ।
13. **dev সার্ভার:** সার্ভিং (`--base` সহ), ওয়াচ, ক্যাশ বাতিল, লাইভ রিলোড, এরর ওভারলে।
14. **scaffold:** `init` আর `new page/layout/component/post`।
15. **ডকুমেন্টেশন:** `example/` পূর্ণ করা, বাংলা `README.md`, সব end-to-end টেস্ট।
16. **রিলিজ যাচাই:**
    - অংশ ২৪-এর প্রতিটি মানদণ্ড একটি একটি করে যাচাই।
    - **বাইরের কাউকে দিয়ে পরীক্ষা:** এমন একজন HTML জানা ডেভেলপার, যে প্রজেক্টটি আগে দেখেনি, শুধু README-র প্রথম অংশ পড়ে ১০ মিনিটে একটি নতুন পেইজ, একটি কম্পোনেন্ট আর একটি Markdown পোস্ট যোগ করবে। কোথায় আটকাল তা লিখে রাখা হবে, আর README বা এরর মেসেজ ঠিক করা হবে। (এটি মানুষের কাজ; Claude চেকলিস্ট আর পর্যবেক্ষণ লেখার টেমপ্লেট বানিয়ে দেবে।)
    - npm-এ প্রকাশ করবেন মালিক নিজে।

## ২৪. গ্রহণযোগ্যতার মানদণ্ড (Definition of Done)

- `npm ls`-এ কোনো ডিপেন্ডেন্সি নেই। ব্যবহারকারী প্রজেক্টে কোনো কনফিগারেশন ফাইল লাগে না।
- `node --test`-এর সব টেস্ট পাস করে, Node 22, 24 আর 26-এ Linux আর Windows-এ, আর Node 24-এ macOS-এ।
- উদাহরণ সাইটের কোনো `.alo` ফাইলে `import`, লোকাল `<link rel="stylesheet">` বা লোকাল `<script src>` নেই, তবুও সব কাজ করে। (বাইরের ফন্টের stylesheet লিংক চলে।)
- উদাহরণ সাইটে সব লজিক `<template>` ট্যাগে।
- `example/`-এ `node alo build` এরর ছাড়া চলে, আর `dist/` যেকোনো সাধারণ স্ট্যাটিক সার্ভারে ঠিকমতো কাজ করে: সব পেইজ, স্টাইল, মেনু, FAQ ক্লিক, Counter আর Markdown ব্লগ পোস্ট। খসড়া পোস্ট `dist/`-এ নেই।
- `node alo build --base /repo/`-এর আউটপুট `/repo/` সাব-পাথে সার্ভ করলে সব লিংক, ছবি, CSS আর JS কাজ করে।
- `dist/`-এর CSS মিনিফাই করা, আর সব asset-এর নাম হ্যাশসহ। `sitemap.xml`-এ সব পাবলিক পেইজ আছে, absolute URL সহ।
- `dist/`-এর কোনো ফাইলে কোনো রিঅ্যাক্টিভ রানটাইম নেই। যে পেইজে কোনো `<script>` নেই, তার HTML-এ `components.js` বা পেইজ JS যুক্ত হয়নি।
- `node alo dev` চালিয়ে যেকোনো `.alo`, JSON, Markdown বা CSS ফাইল সংরক্ষণ করলে ১ সেকেন্ডের মধ্যে রিলোড হয়।
- এই ভুলগুলোতে সঠিক ফাইল আর লাইনসহ পরিষ্কার এরর বা সতর্কবার্তা আসে: ভুল কম্পোনেন্ট নাম, ভুল প্রপ নাম, ভাঙা JSON, অসমর্থিত YAML, বন্ধ না করা ট্যাগ, ডেটা বদলানোর চেষ্টা, `<li if>`, কম্পোনেন্টে লজিক।
- `npx @msilabs/alo init my-site && cd my-site && npm install && node alo dev` নতুন ব্যবহারকারীর জন্য প্রথমবারেই কাজ করে।
- বাইরের একজন HTML জানা ডেভেলপার README-র প্রথম অংশ পড়ে ১০ মিনিটে নতুন পেইজ, কম্পোনেন্ট আর Markdown পোস্ট যোগ করতে পেরেছে।
- সাধারণ এলিমেন্টে Alpine.js/MiniJS-এর `:`/`@`/`x-` অ্যাট্রিবিউট আউটপুটে অপরিবর্তিত থাকে।
